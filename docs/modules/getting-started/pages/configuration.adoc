= Configuration

[role="_abstract"]
{prod} reads configuration from environment variables. For local development, create a `.env` file in the repository root.

== Required variables

|===
| Variable | Description | Example

| `GITHUB_TOKEN`
| GitHub personal access token with `repo` scope. Used to open pull requests and resolve your GitHub identity.
| `ghp_abc123...`
|===

== LLM provider variables

Configure at least one LLM backend. The agent uses the active provider selected in *Settings > AI Providers*.

|===
| Variable | Description

| `ANTHROPIC_VERTEX_PROJECT_ID`
| Google Cloud project ID for Claude via Vertex AI.

| `GOOGLE_CLOUD_REGION`
| Vertex AI region (default: `global`).

| `GEMINI_API_KEY`
| API key for Google Gemini models.

| `OLLAMA_BASE_URL`
| Base URL for a local Ollama instance (e.g., `http://localhost:11434`).
|===

== Optional variables

|===
| Variable | Description | Default

| `PORT`
| HTTP port for the server.
| `3000`

| `DATABASE_URL`
| PostgreSQL connection string. When unset, PGlite (embedded Postgres in WASM) is used.
| _(unset — PGlite)_

| `PGLITE_DATA_DIR`
| Directory for persistent PGlite storage. When unset, data is in-memory and resets on restart.
| _(unset — in-memory)_

| `KNOWLEDGE_DIR`
| Path to knowledge packs directory.
| `/knowledge` (container) or `pg_seed/eclipse-che` (local)

| `JIRA_BASE_URL`
| Jira instance base URL.
| `https://redhat.atlassian.net`

| `JIRA_EMAIL`
| Jira account email for "assigned to me" source seeding.
| _(unset)_

| `JIRA_TOKEN`
| Jira API token.
| _(unset)_
|===

[[model-selection]]
== Model selection

The agent uses two model tiers. The *deep* tier runs analyze, implement, and review; the *fast*
tier runs short, high-volume calls such as issue scoring, priority checks, and story-point
estimation.

Defaults live in one place — `packages/agent-backend/src/llm/defaults.ts` — rather than being
repeated at each call site. Both tiers default to Claude Haiku 4.5.

IMPORTANT: Model ids are not interchangeable between providers. The Anthropic API uses a
`-YYYYMMDD` suffix (`claude-haiku-4-5-20251001`); Vertex AI uses `@YYYYMMDD`
(`claude-haiku-4-5@20251001`).

|===
| Variable | Description | Default

| `VERTEX_CLAUDE_MODEL`
| Deep-tier model for Vertex AI. Also seeds the Vertex provider row on first start.
| `claude-haiku-4-5@20251001`

| `VERTEX_FAST_MODEL`
| Fast-tier model for Vertex AI.
| `claude-haiku-4-5@20251001`

| `ANTHROPIC_FAST_MODEL`
| Fast-tier model for the direct Anthropic API.
| `claude-haiku-4-5-20251001`

| `GEMINI_MODEL`
| Model for the Gemini provider.
| `gemini-3.6-flash`
|===

To run code generation on a larger model while keeping the cheap calls on Haiku, pin the deep
tier only:

[source,bash]
----
VERTEX_CLAUDE_MODEL=claude-sonnet-4-6@default
----

NOTE: A provider row stores its own `model`, editable in *Settings → AI Providers*. These
variables seed that row the first time the database is created; afterwards the stored value
wins. With an in-memory PGlite (no `PGLITE_DATA_DIR`) the database is recreated on every
restart, so the variables apply every time.

== Example `.env` file

[source,bash]
----
GITHUB_TOKEN=ghp_your_token_here
ANTHROPIC_VERTEX_PROJECT_ID=my-gcp-project
GOOGLE_CLOUD_REGION=global
----

IMPORTANT: The `.env` file contains secrets. It is gitignored and must never be committed.
